# QML utility prototype

This folder is the entry point of the same installable project as `qml_tricks`.
Reuse canonical research implementations through the integration layer; keep
utility-specific implementation and evidence here. Run from the root with
`python -m QML_utility...`. Do not modify, hide or relabel the
original repository's studies. No publication or visibility change is authorized.

Start from `catalog.json`, the matching evidence guide and replication protocol.
Separate published success, native circuit verification, local protocol audit
and full paper reproduction. No record currently certifies a locally reproduced
classical-data paper win. Never invent an accuracy from a plot.

For a new project start with recommend.py and PRACTICAL_WORKFLOW.md. The
method_library.json portfolio is an explicit exploratory engineering route,
separate from the ten published-success cases. Its tested implementations are
not extra advantage claims. run_project.py requires an explicit numeric data
contract, split regime and opt-in config; do not force other modalities into it.
All new utility implementation and docs stay in this folder. Use companion_map.json
to connect preserved repository techniques. Essential diagnostics call the main
library directly; supervised QNG reuses its geometry. Offline exported students
must remain independent of both native-model packages and quantum SDK imports.

The installable CLI uses __main__.py. Preserve the reference-versus-batched
adapter distinction: batching changes the classical head and caps, not the
native circuit or evidence label. Multi-run plans must be frozen before fitting;
overlapping resamples do not yield independent-replication confidence intervals.
Offline students must exclude prior teacher fit/selection/evaluation records
from their gate, retain the frozen head and block export on any failed gate.
Never retain a teacher or SDK callback in a supposedly zero-query student.

A dataset resemblance is a hypothesis, not a performance guarantee. Preserve
matched access, regularized/domain-specific controls, all trials and negative
results. Do not shrink a long continual-learning task to a tiny IID benchmark
and call it a reproduction. No automatic two-component PCA or generic VQC fallback.

Scope non-winning results to the tested dataset/configuration/budget. Do not infer
method-wide uselessness. More effective training or different data structures
remain hypotheses requiring a prospective comparison. Preserve mathematical
constraints such as exact classical equivalence and lost input information.
Use experiment_outcomes.json and protocols/contextual_followup.json; never edit
an old record to turn a follow-up into the original result.

The ten catalog cases are publication-scoped candidates, not ten local wins.
plan_project.py emits draft contracts only; blank project details and paper-level
blockers must be resolved before an experiment can be considered executable.

Upstream source is pinned and inspected, not automatically executed or vendored.
Review licenses, dependencies, output paths and data deserialization first.
Only export successful-use recommendations after held-out, matched-cost evidence.
